# シミュレーション構成と実機の等価性

## 物理構成の違い

### 実機構成

```
          [Tello ドローン]
          底面に marker_23 貼付
               ↑ (ARマーカー)
  ================================  ← 地面
       [固定カメラ・上向き]
        /dev/video_tello
```

- **カメラ**: 地面に固定、天井（上方）を向いている
- **マーカー**: ドローン底面に貼付、カメラ上空を飛行
- **制御目標**: ドローンがカメラの真上に来るよう移動させる

### シミュレーション構成（`sim_landing.launch.py`）

```
       [Tello ドローン（Gazebo）]
       搭載カメラ・下向き改修
               ↓ (カメラ視点)
  ================================  ← 地面
       [marker_23 固定配置]
```

- **カメラ**: ドローンに搭載、地面（下方）を向いている
- **マーカー**: 地面の原点に固定
- **制御目標**: ドローンの真下にマーカーが来るよう移動させる

---

## 制御スタックとしての等価性

一見すると上下が逆だが、**制御ループの入出力は等価**である。

### 等価である理由

どちらの構成でも次のサイクルが成立する：

```
マーカーが画像に映る
      ↓
ar_detector: マーカーのピクセル座標 → TF (camera_cv_frame → marker_23_frame)
      ↓
pid_controller: camera_center_frame からの誤差 → pid_vel
      ↓
cmd_multiplexer: pid_vel を cmd_vel として転送（自動モード時）
      ↓
TelloPlugin / tello_driver: cmd_vel に従ってドローンを移動
      ↓
マーカーが画像中心に近づく（収束）
      ↓
auto_lander: 一定時間収束を検出 → "land" 送信
```

### 符号（移動方向）の等価性

| ドローンが右（+x）に動く | 実機 | シミュレーション |
|--------------------------|------|----------------|
| カメラからの視点 | カメラ固定・マーカーが右に動く | カメラも右に動く・マーカーが相対的に左へ |
| 画像内マーカー位置変化 | 右 (+x) へずれる | 左 (-x) へずれる |
| PID 出力（誤差 → 補正） | ずれが増えた → 左へ戻す | ずれが減った → 追従完了 |

一方、**実際にはどちらの構成でも同じ符号で収束する**。

- **実機**: 地面カメラは固定。ドローン（＝マーカー）が右に動くと、カメラから見てマーカーは右にずれる。PIDはそのずれをゼロにしようとするため、ドローンを左に戻す指令を出す。収束する。
- **シミュレーション**: カメラはドローンに搭載されており、ドローンが右に動くとカメラも右に動く。地面に固定されたマーカーは相対的に左にずれる。PIDはそのずれをゼロにしようとするため、ドローンを右（カメラをマーカー上へ）に戻す指令を出す。収束する。

両者でドローンはマーカーの真上に収束する。**制御ロジックは同等**。

## シミュレーションで検証できること

| 検証項目 | 可否 |
|---------|------|
| ar_detector がマーカーを検出し TF を配信できるか | ✓ |
| pid_controller が収束方向に速度指令を生成するか | ✓ |
| cmd_multiplexer が RB ボタン時に自動モードへ切替できるか | ✓ |
| auto_lander が収束を検出して着陸コマンドを送るか | ✓ |
| TF ツリー（camera_cv_frame → camera_center_frame → marker_23_frame）が正しく接続されるか | ✓ |
| tello_action サービスの送受信が正しく動作するか | ✓ |

## シミュレーションでは検証できないこと

| 項目 | 理由 |
|------|------|
| USB カメラの安定性・fps | 実デバイスがないため |
| 実ドローンの飛行特性（オーバーシュート等） | Gazebo の物理モデルは簡略化されている |
| ネットワーク遅延による制御への影響 | UDP 通信は発生しない |
| 実機カメラの歪み・露出変動 | Gazebo カメラはノイズのみ |

## 注意事項

### カメラ向きの確認

`tello_sim.urdf` のカメラジョイントは `rpy="0 1.5708 0"` で下向きに設定している。
起動後に `/image_ar` トピックを確認してマーカーが映っていない場合は
`rpy="0 -1.5708 0"` に変更して再ビルドすること。

### 制御符号の確認

実機とシミュレーションで PID の x/y 符号が逆になる場合は `docs/debug_pid_sign.md` を参照。
